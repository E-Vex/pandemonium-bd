## 2. The script

`tests/xvfb/a010_controls_confirm.sh` (438 lines, executable, re-runnable, no source modified). It is the persisted, self-contained form of the pass — the brief's steps (a)–(e) in order:

1. **Hard requirement check** (§1's table, programmatically): `Xvfb`, `python3`, `cargo` (rustup's `~/.cargo/bin` is added to `PATH` if needed) must exist or the script exits with an `A-010 BLOCKER:` line; `python-xlib` is pip-installed if importable-not (the §9 XTEST vehicle). A blocker is reported, never substituted around.
2. **Userland library bootstrap** (only when the system lacks EGL/XTEST/xkbcommon-x11): `apt-get download` + `dpkg -x` into `${A010_USERLAND:-$HOME/.local/share/pandemonium/userland-libs}` (no root), the unversioned `libxkbcommon*.so` symlinks winit dlopens, the glvnd vendor ICD JSON, and — only when `pkg-config --exists alsa` fails — the alsa dev tree with a userland-prefix `alsa.pc`. The official run below exercised this path from scratch (fresh `$HOME/.local/share/pandemonium/`).
3. **Xvfb launch**, run directly on `:99` (no `xvfb-run`, no window manager), screen `1280x800x24` — at least the 800×600 window — with stale `/tmp/.X99-lock`/socket cleanup, a wait for the socket, and `trap cleanup EXIT`.
4. **Build**: `cargo build -p pandemonium-client --release` (the brief's step b).
5. **The check sessions** (an embedded python-xlib driver; steps c–e). Each check is one fresh client session: launch the release binary under `:99` with `--seed 41008`, discover the new window by diffing the root window's children (by XID), `set_input_focus` on it (no WM), inject keys with `xtest_fake_input` at a 0.35 s press/release cadence (the §9 range), optionally wait out a live-match interval, then send the `WM_DELETE_WINDOW` ClientMessage (the graceful close) and wait for exit. The session's stdout/stderr — including the exit evidence line — is captured whole to `target/a010-evidence/<check>.log`, and the verdict parses the line against the expectation (screen name, tick floor/ceiling, matches-started count, or the `--frames` smoke summary for c0).
6. **Verdicts**: one `PASS`/`FAIL` per check with the observed evidence line printed inline, a final `N passed, M failed` summary, and exit code 0 iff everything passed.

Re-running: `bash tests/xvfb/a010_controls_confirm.sh` (all checks) or `bash tests/xvfb/a010_controls_confirm.sh c6 c7` (a subset — the failure-retry loop). Knobs: `A010_EVIDENCE_DIR`, `A010_USERLAND`, `A010_DISPLAY`, `A010_SEED`. The evidence directory defaults inside `target/` so a run never dirties the tree.

## 8. Deviations, assumptions, and limitations

- **Two supplementary checks beyond the brief's list (c11, c12).** The exit evidence line names the screen "confirm screen" for both pending actions, so the brief's c6/c9 checks alone cannot distinguish the Restart confirm from the Quit confirm. c11/c12 (Proceed on each) close that gap behaviorally — the drop lands at the main menu with "1 match started this run", the restart at the match with a fresh tick. Verification only; no source changed.
- **The restart/not-restart discriminator is tick arithmetic, not screen identity alone.** The assumptions are stated here: `pandemonium_sim::TICKS_PER_SECOND = 30` (pinned by calibration: tick 455 after 14.5 s of live match), the paused host freezes its tick (pause freezes the clock without a catch-up burst — unit-pinned in `host.rs`), and a restart is drop + reconstruct (A15) landing on a fresh host. The thresholds: ≥ 300 ticks behind a pause/confirm screen (10 s of live match), ≥ 400 for a same-match continuation (a restart ≤ POST_RESUME + cadences old cannot reach it), ≤ 150 for a fresh restart. All observed values sat far from every threshold (471/470 vs 300; 582 vs 400; 21 vs 150).
- **One fresh client session per check.** The exit evidence line only prints on exit, so each check drives a fresh launch from the main menu to its own checkpoint, then closes. Cross-check state is never reused — a failure in check N cannot contaminate check N+1, and each session is independently reproducible (`--seed 41008` pre-fills the New Match seed).
- **Keyboard only; no pixel verification.** The brief's checks are keyboard flows, and the decisive evidence is behavioral (which successor screen, which tick). No screenshot was pixel-scanned for the focused row's bright plate (the §9 mouse-targeting lesson) — the focused-plate claim for Cancel rests on the Enter-behavior (c7): only focus-at-Cancel produces "pause menu, frozen tick". Likewise the "rendered surface" claim rests on the app reaching and holding each screen state across real frames without a rendering crash, gated by c0's 60 presented frames; it does not claim a human judged the visuals — that remains DEBT-008's human half (the A14 sessions).
- **The audio arm under Xvfb is the null fallback** ("no device — null fallback" in every session log) — expected and honest: Xvfb has no `/dev/snd`, the machine cannot hear, and no audible-sound claim is made anywhere in this report.
- **A-009's focus/minimize auto-pause paths were not exercised** — they need a real WM-focus-loss signal, which a WM-less Xvfb does not produce. That was already A-009 §11's honest limit (logic-only machine verification); nothing in this pass changes it.
- **The script's userland bootstrap is Debian-shaped** (`apt-get download` against the trixie lists; `libasound2t64` is named for the time-t rename). On a sandbox with the libraries already present the bootstrap is skipped entirely (a `needs_userland` probe); on a non-Debian sandbox it would report the blocker honestly rather than fail obscurely.
