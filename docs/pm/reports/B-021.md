# B-021 — AI plan tuning overrides (report)

**Branch** `b/B-021-ai-overrides` · **Base** master `6eaa82b` (`6eaa82bc375398809eb7da7a1ab04767737cf52e`, master after B-020, verified against `origin/master` before the first commit) · **Status**: done, all verification green, goldens unmoved.

Implements the B-021 work package of ADR-0201 Phase 2 (the closing package): mission-controlled AI tuning with byte-exact defaults. A mission may override the scripted Alpha opponent's six pacing values inline through an optional `ai_settings` block — `wave_timer_ticks`, `wave_size`, `min_wave`, `army_cap`, `worker_target`, `first_attack_delay`, each an independent `Option<u32>`; `None` everywhere is the script's own consts, byte for byte. The pipeline: content schema → defs → loader → bundle (seam + mission-id tail) → `sim_api::AiSettings` on `MissionData` (carried, never read by the sim) → `engine::ai_host::alpha_plan` (the effective-value invariants) → `ai::scripted` (`AiPlan` gains the `Option` fields; the controller reads `override.unwrap_or(CONST)`). The mission-less path is untouched (FD-1); the RNG consumption order is untouched (the identity tests pin it).

## Where the checks live (the loader/engine split)

The brief says "loader checks on effective values". The content loader cannot see the script's consts: the dependency law (plan §4, pinned by `tests/architecture_law.rs`) puts `pandemonium-ai` above `pandemonium-content`, and hardcoding the defaults in content would duplicate the tuning truth and drift on the next retune. The checks therefore split at the seam where the knowledge splits, documented in both places:

- **Loader** (`content/src/loader.rs`): every provided value must be positive; the pairwise invariants `min_wave <= wave_size` and `wave_size <= army_cap` must hold wherever both members of a pair are provided. These are all the shapes the file can see.
- **Engine** (`engine/src/ai_host.rs::alpha_plan`): every effective value positive, and the effective `min_wave <= wave_size <= army_cap` — the first place the overrides and the consts they replace meet. This catches the cross-default shapes the loader structurally cannot (a solo `min_wave` above the *default* `wave_size`, a solo `wave_size` above the *default* `army_cap`), loudly, before any controller runs. Pinned by two `#[should_panic]` tests (values derived from the consts: `2 * WAVE_SIZE`, `2 * ARMY_CAP`).

The defaults satisfy the invariants (4 <= 10 <= 16), so a mission the loader accepts never trips the engine assert unless it crosses a default it could not see.

## Acceptance

All in `tests/mission_ai.rs` unless noted:

- **All overrides None** (`an_all_none_ai_settings_block_is_the_byte_exact_default`): a mission with an explicit all-`None` block riding the sim reproduces the mission-less baseline exactly — the flagship golden, the command-stream digest, and both controller RNG states at ticks 300 and 7200. The RNG consumption order is pinned by the same equality (the streams are identical, so the draws fell identically). The mission-less baseline itself is pinned against the recorded values (`the_missionless_flagship_baseline_is_pinned`), cross-checked against the registered golden.
- **Override tests derive their values from the consts, never hardcoding them** — each compares a tuned run against a same-shape all-`None` run (same seed, same world, same objectives):
  - `wave_timer_ticks = Some(1200)` (= `WAVE_TIMER_TICKS / 2`): the first march is unchanged (army-gated in this content — the first march fires when the army crosses `MIN_WAVE` under an already-passed timer, so the halved *cadence* does not move it; the observation is in the test's comment and the report), and the first divergent march issues strictly earlier on both slots (every re-arm fires at half the interval).
  - `first_attack_delay = Some(4800)` (= `2 * WAVE_TIMER_TICKS`): the first march issues strictly later on both slots.
  - `min_wave = Some(8)` (= `2 * MIN_WAVE`): the first march waits for the larger army crossing — strictly later on both slots.
  - `worker_target = Some(14)` (= `WORKER_TARGET + 4`): at tick 4800 the tuned side fields strictly more workers on both slots (baseline `13/15`, tuned `15/17`; the baseline's pending-expiry overshoot is noted — pre-existing acting-blind behavior, untouched).
  - `army_cap`: the effective-value law pins `wave_size <= army_cap`, and the default wave size (10) already sits above this content's observed army (max 8 and 6 on the two slots), so a *measurable* cap carries the paired wave size — `wave_size: Some(4), army_cap: Some(4)` (both = `MIN_WAVE`): the army never exceeds 4 on either slot while the baseline's exceeds it on both.
- **A mission with overrides has a different id**: pinned at the content level (`ai_settings_are_identity_bearing_only_when_carried` — no-op shapes keep the id; every carried tuning shape is its own id) and used by the replay test.
- **replay-verify round-trip passes**: `a_tuned_mission_replay_roundtrips` — a recording of a tuned mission (1200 ticks) carries the tuned mission's id (different from the no-block mission's), validates structurally, re-simulates to every checkpoint and the final hash through `run_command_log_with_mission`, and encode/decode round-trips the id (AUD-002's codec path). ## Open issues

None blocking. Two boundaries recorded for the owner:

1. **The cross-default assert panics rather than errors.** A mission like solo `min_wave: Some(20)` passes the loader (content cannot see the default `wave_size` 10) and fails the engine assert at plan construction — in the client, a crash rather than a menu message. This is the loudest possible failure at the earliest point the knowledge exists, and the shape is an authoring error exactly like a loader rejection; but if the owner prefers a `Result` channel (alpha_plan returning errors), that is a follow-up brief — it ripples every call site's signature again.
2. **The workforce overshoot is pre-existing.** The baseline's alive-worker count drifts a few above `WORKER_TARGET` (the pending-expiry re-issue of the acting-blind design — the controller cannot see its queue). The `worker_target` override still moves the count measurably (the target dominates: 10 → 13–15 vs 14 → 15–17 at tick 4800), but a future brief could tighten the pending bookkeeping (e.g., expiry keyed to the issuing cooldown rather than the doubled build time). Not B-021's business to change — it is behavior, and the goldens pin it.
