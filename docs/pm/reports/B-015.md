Implements the B-015 work package of ADR-0201 Phase 2: an optional `fog_preset` mission field carried from the file through the content seam into the initial `FogState`, and the `MissionObjectives` → `MissionData` rename that makes the mission input the single carrier for later mission config. **How `advance_vision` treats Visible tiles (crates/sim/src/vision.rs, read pre-change).** Each tick it snapshots every player's currently-`Visible` tiles and clears them to `Hidden` in the same fused pass (B-006), re-marks every tile inside any friendly vision radius `Visible`, then `promote_visible_to_explored` demotes every previously-`Visible` tile that was not refreshed this tick to `Explored`. So yes — unseen `Visible` tiles are demoted every tick. An init-only "whole map Visible" would therefore collapse to `Explored` outside the radii within one tick, and the `Visible` preset is implemented as a persistent reveal flag in `FogState` read by the filter, exactly as the brief anticipated.

## Notes and decisions

- **Authored shape.** The RON spelling is `fog_preset: Some("Explored")` — explicit `Some(...)`, the schema's established Option convention (`target_kind: Some("...")` uses the same shape; RON 0.9 rejects a bare string for an Option field with `Expected option`).
- **schema_version stays 1.** The new field is optional with a default; the loader does not force a bump (FD-10), and no golden moved.
- **Domain separation in the mission-id encoding.** The non-default tail is `true` + `0xF0` + discriminator, self-describing so a future tail field appended after it can never misparse these bytes; `Default` emits nothing at all, which is what keeps the pre-B-015 missions byte-identical.
- **`advance_vision` untouched.** The `Visible` preset does not change the stage-9 pass; the persistent reveal lives in `FogState` and is consulted by the readers (`tile()`, `player_view`). This is the only shape that keeps the pass's B-006 fused-sweep reasoning and FD-8's filter-only discipline intact.
- The frozen content (no files under `content/factions` or `content/rules` added; variants stay inline) and every golden were verified unmoved at the end of the run.
