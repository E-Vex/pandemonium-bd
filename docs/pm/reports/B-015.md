## 1. Summary

Phase 2's smallest safe first package (the planning report §G) landed exactly as
briefed: the mission schema gains the fog preset (`default | explored | visible`,
schema v1 → v2 with the forward-only migration), the Phase 1 type
`MissionObjectives` is renamed `MissionData` (the owner's E3 ruling) and gains
`fog_preset`, and `Sim::build`'s fog init is parameterized by the preset —
`FogPreset::Default` reproducing the historical all-Hidden init byte-for-byte.
The type rename establishes the carrier every later Phase 2 package
(`ai_settings`, restrictions) extends. All four protected baselines were
re-derived live and are bit-identical: content hash `0x9bc18c521107b262`, map id
`0xd38136401ab02ff1`, demo `0xb6fff6659cfb7709`, flagship `0x6e9a18bd7c5f699f`.
No STOP condition fired.

**The identity rule this package establishes (binding for all later Phase 2
packages):** `encode_mission` appends bytes for post-Phase-1 mission fields only
when they are non-default. A default-valued mission therefore encodes to the
exact Phase 1 byte stream — `crossroads_01`, now declared at schema v2 with
`fog_preset: Default`, keeps its Phase 1 mission id (pinned by test (b) below),
and nothing pins mission ids in CI, so no golden could move anyway (the planning
report's A5 disposition).

## 5. FD compliance (the brief's architecture-law row)

- **FD-5:** the preset is a plain enum — no numbers at all, let alone floats.
- **FD-6:** the preset reaches the sim only through `ContentTree::mission_data`
  → `MissionData.fog_preset` → `Sim::with_mission`; the sim never sees a file.
- **FD-7:** the preset is deterministic and player-symmetric — every issuer's
  filter starts identically; the AI reads the same `PlayerView.fog` as the human.
- **FD-8:** the preset changes the filter's *initial state* only — pinned by the
  hash-equality assertions inside every preset test (state hashes identical to
  the mission-less path at every tick).
- **FD-10:** mission schema v1 → v2 with the one-step migration; v1 files keep
  loading and keep their identity (the default appends no bytes).

## 6. Deviations, risks, notes

- **The `Visible` preset's observable settling (documented, by design):** the
  seed is all-tiles-`Visible`; `advance_vision`'s normal demotion then settles
  tiles outside friendly radii to `Explored` after the first pass (the ADR's
  "initial state" letter — the preset seeds the filter; the pass owns the
  evolution). Observably `Visible` ≡ permanently-explored + live vision; the
  distinction from `Explored` is the seeding itself (pinned at the `FogState`
  level) and the mission id. Risk R6 from the planning register (the AI seeing
  the enemy base from tick 0) therefore does **not** materialize under the
  ADR-as-written semantics: no entity outside a vision radius is ever returned
  by `player_view`, on any preset. Recorded here so the owner can rule on a
  persistent no-fog mode separately if the Generals-style "no fog" is wanted —
  that would be a new, named change to `advance_vision`, deliberately not
  smuggled into this package.
- **`mission_objectives` → `mission_data`** is an API rename inside the
  workspace's own seam (the planning report's B3 option (b), the owner's E3
  ruling); all consumers updated in the same commit; no deprecation shim (the
  repo has no external consumers — `publish = false`).
- The sandbox needed the usual ALSA shim (B-010…B-014 precedent) and one
  symlink fix inside it; no repo file is affected.
