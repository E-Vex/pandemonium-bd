## 8. Risks and surprises

- **Branch protection has never been turned on.** MP-8 and the aggregator
  exist precisely so protection can require one immutable check — and the
  repo's master branch is unprotected (§3). Until the owner enables it,
  "required status check" is a property of the workflows' good behaviour, not
  of GitHub's enforcement. This is the single most actionable finding of the
  recovery.
- **The aggregator's red path has never fired live.** Every run since it
  exists is green; the failure branch (a needed job red/cancelled/skipped →
  ci-required fails) is verified by reading the committed script, not by
  observation. A future red inner job will be its first live proof — expect
  the required check to go red *with* it, which is the design working.
- **The record was nearly lost twice over.** Not only was the B-002R report
  never committed: its task ID survives only inside a YAML comment. Had that
  comment been reworded, the task would have been unrecoverable by name.
  MP-9's "the repo is the record" rule is the direct lesson.
