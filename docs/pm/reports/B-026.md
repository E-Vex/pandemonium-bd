## 3 Evidence per acceptance criterion

**The progress file, beside settings.cfg (ADR-0201 §6).**
`campaign_progress.cfg` resolves through the same `config_dir_from` as
`settings.cfg` (pinned by `progress::tests::
the_progress_path_shares_the_config_directory_with_settings`); the format
is the ADR's letter — one `<mission-id>=completed|skipped` per line, per-key
salvage, unknown ids parse and survive a load-save cycle (the module cannot
know the tree; a friend's file must not lose lines). 13 unit tests incl. a
filesystem round-trip through `load_from`/`save_to` and the
nested-parent-directory creation. Command:
`cargo test -p pandemonium-client --bins -- progress::` → 13 passed.

**The Campaign row (B-025's law).** The row exists exactly when
`KeyContext.has_campaign` / `MenuInput.has_campaign` (both read
`tree.campaign.is_some()`); campaign-less the main menu is exactly its
four rows. Pinned by `screens::tests::
the_main_menu_gains_a_campaign_row_only_when_the_tree_carries_one`
and `ui::tests::the_main_menu_renders_the_campaign_row_only_when_present`.

**Unlock semantics (§6's rules).** Chapter N+1 unlocks when chapter N is
completed **or** skipped; a challenge unlocks when its chapter is
**completed** (A-211); an entry with its own record is always startable
(no soft-locks from stale files, A-214). Pinned by
`the_unlock_rule_gates_chapters_on_their_predecessor`,
`a_skip_unlocks_the_next_chapter_but_never_the_challenge`,
`an_entry_with_its_own_record_is_startable_even_from_a_stale_file`, and
the integration pins over the real content
(`a_progress_file_builds_its_records_into_the_snapshot`).

**Skip, both affordances (§6's second skip).** The campaign screen's Skip
row: the machine updates its snapshot, the app records + persists (the
temp-file evidence: `a_campaign_skip_records_persists_and_unlocks_the_next_chapter` — the file contains `crossroads_01=skipped` and a fresh snapshot
resolves the unlock). The pause menu's Skip Mission: row 6 (rows 0-5
unchanged — the Xvfb focus arithmetic), only over a mission
(`KeyContext.live_mission`), confirm-gated, landing on the main menu with
the host dropped (`the_pause_menu_skip_drops_the_mission_and_records_it`);
a plain match's pause menu keeps six rows
(`a_plain_matchs_pause_menu_keeps_six_rows`).

**Victory recording.** The end-screen promotion records the mission as
completed when the player won (`a_mission_victory_records_and_unlocks_the_campaign` — the file contains `crossroads_01=completed`, a fresh snapshot
shows chapter 2 available and the challenge unlocked); a plain match
records nothing; a skip upgrades on a later win and an already-completed
replay writes nothing (`a_victory_upgrades_a_skip_and_an_already_completed_replay_writes_nothing`). The mission end screen's VICTORY subline reads
"Mission complete: \<name\>".

**The campaign is a menu peer, never a gate.** The plain mission picker,
New Match and every mode are untouched (the picker's tests unchanged); the
Campaign row's activation cannot lock anything — locked entries are inert
*inside* the campaign screen only.
