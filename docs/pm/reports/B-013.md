## 2. The integration test design

`tests/mission_phase1.rs` (new, three tests) loads the repository's real content tree,
resolves the real mission through the content seam, and drives the real simulation —
no sandboxed mission strings, no hand-built objective sets:

- **`crossroads_01_resolves_command_center_objective`** —
  `ContentTree::load_dir(&repo_content())` (the repo's directory-loading constructor —
  the brief's sketch says `from_dir`, which is the loader layer's `SourceMap` method;
  wording only, §6 D-5), then `tree.mission_objectives("crossroads_01", PlayerId(0))`.
  Asserts exactly two objectives; objective 0 is the required `Destroy` with
  `target_kind: Some(KindId)` — pinned to the tree's own `command_center` entity index,
  proving the seam resolves the string to the same id the world's kinds carry; objective
  1 is the optional `BuildTrain` of four workers, pinned to the `worker` index the same
  way. Determinism: two resolutions compare equal, and `mission_id("crossroads_01")`
  is stable across calls.
- **`command_center_destruction_completes_mission_with_other_structures_standing`** —
  the core behavioral test. The world builder (`command_center_world`) reads the
  command-center `KindId` out of objective 0's resolved parameters, then builds a
  `TrivialWorld` with kinds `0..=cc_index`: every index below the target is a 10-hp,
  0-regen structure that survives; the target index itself is a 1-hp, −1-regen
  structure that dies on tick 0 (the surgical strike, the repo's standing decay idiom).
  Spawns: the mission player's surviving structure (kind 0), the enemy command center
  (the target kind), and the enemy's second, surviving structure (kind 0). One step of
  `Sim::with_mission(&world, two_player_setup(), objectives)` then proves all four
  required behaviors: (a) `ObjectiveState { index: 0, Completed }` fires; (b)
  `MatchEnded` fires with `PlayerId(0)` as winner and `sim.outcome()` names the same;
  (c) the snapshot still contains an entity with `owner == PlayerId(1)` and
  `kind == KindId(0)` — the enemy side stands, so the resolution is NOT the elimination
  rule — and no command-center entity remains; (d) no
  `ObjectiveState { index: 1, Completed }` ever fires: the optional BuildTrain is
  incomplete (no four workers exist) and does not block victory. STOP conditions 3 and
  4: not fired — the surviving structure is in the world, and the mission ends with the
  mission player as winner.
- **`mission_less_path_is_byte_equivalent`** — the same world and setup through both
  constructors: `Sim::new` (which never reads mission data — the fixture is content,
  not code) and `Sim::with_mission`. Asserts identical state hashes before and after
  the step (mission state is derived, the A-066 pattern — the byte equivalence the
  test's name promises, pinned here over the real resolved mission); asserts the
  mission-less path resolves nothing (`outcome()` is `None` — the enemy's surviving
  structure stands, so elimination holds its fire too) and emits no objective-state
  events; and asserts the contrast that proves the seam: the same hashed state carries
  a different derived outcome — the wrapped match resolves, the plain one keeps
  running. STOP condition 6: not fired.
