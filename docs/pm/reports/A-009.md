## 6. Deviations and assumptions

- **A-1009 (assumption, this brief): the winit 0.30 minimize signal is `WindowEvent::Resized(PhysicalSize::ZERO)`.** winit 0.30.13 (the pinned version per `Cargo.lock`) has no `WindowEvent::Minimized` variant; the standard 0.30 signal for minimize is the (0,0) resize (the platform backends emit it on minimize — see winit's own `event.rs:1043-1045` test fixture). `Window::is_minimized()` returns `Option<bool>` (always `None` on Wayland), so the Resized signal is more portable. The pure function takes a `FocusEvent` enum (the wiring layer translates the winit signal), so this assumption is isolated to the wiring layer in `main.rs` and can be revised without touching the pure decision or its tests if a future winit adds a dedicated variant.

The structural fit is pinned by `the_menu_buttons_match_the_machines_focus_indices_on_every_screen` (the Controls screen's button rect is inside the viewport at 1280×800); a 800×600-specific test was not added because the menu pass already centers the panel and the layout is deterministic.

## 8. Risks and surprises

- **The winit 0.30 minimize signal.** The brief said "use the signal that is reliable in the pinned winit version and report the version and the signal." winit 0.30 has no dedicated `Minimized` variant (it was present in 0.28's changelog but removed in 0.29's window-state rework). The reliable signal is `WindowEvent::Resized(PhysicalSize::ZERO)` (the platform backends emit it on minimize — winit's own test fixture synthesizes a minimize this way at `event.rs:1043-1045`). `Window::is_minimized()` exists but returns `Option<bool>` and is `None` on Wayland, so it is less portable than the Resized signal. The pure function takes a `FocusEvent` enum, so this is isolated to the wiring layer and revisable.
- **The Controls screen's table fits the smallest supported window by construction, not by machine-verified capture.** The 16-row table at the tighter pitch fits 800×600 by arithmetic (panel height under 600px); the Xvfb pass would confirm visually but is not run here (see §11).
- **The Confirm screen's "the current match will be lost" subline is ASCII.** Verified by `MatchMode::label()` ASCII test pattern (the Phase 3 trap T8); the string itself is ASCII (`"the current match will be lost"` — all characters < 0x80).
