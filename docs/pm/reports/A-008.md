## 3. Evidence per acceptance criterion

### 3.1 Task 1 — Windows zip: `/` entries under a single root folder — done, method stated

**The method, and why:** the packaging branch runs the `windows-2022` runner image's own Python (`python --version` printed in the step: **Python 3.12.10** at run 38381247847) and the stdlib `zipfile` module. Chosen over 7-Zip and pwsh 7 because (a) entry names must be stored with `/` verbatim — `zipfile` stores exactly the string handed to `ZipInfo`, while `zf.write()` normalises via `os.path.normpath` and would reintroduce `\` on Windows, so the arcnames are built by hand; (b) it needs no new tool download (the image is the pin — the same pin class as the `powershell`/`tar`/`sha256sum`/`unzip` the workflow already relies on), and the same interpreter powers the smoke gate; (c) the file set, compression (ZIP_DEFLATED, level 9), and per-entry behaviour are fully under our control and assertable in the same script.

**The structure, proven twice:**

- **Locally, before any commit:** the exact script was extracted from the parsed YAML and executed against a staging tree holding the real repo file set — `pandemonium-0.1.1-windows-x86_64.zip`, 28 entries (the root folder itself + `content/` + 4 content subdirs as explicit directory entries, then the 22 files), every name forward-slashed, single root, per-entry asserts green.
- **On the dispatch (run 38381247847):** the build log prints `packaged pandemonium-git-00d3839-windows-x86_64.zip with forward-slash entry names under pandemonium-git-00d3839-windows-x86_64/`, and the artifact was downloaded back out of the run and re-verified locally: `unzip -Z1` lists 28 forward-slash entries under the one root; both new gates PASS on it (§3.3–3.4).

**The file set is otherwise identical:** `unzip -Z1` of the published v0.1.0 zip vs the packaged one, backslash-normalised, diffed empty — the same 22 files at the same relative names (`LICENSE`, `pandemonium-client.exe`, `pandemonium-tools.exe`, `QUICKSTART.md`, `README.md`, `THIRD_PARTY_NOTICES.md`, and the 16-file `content/` tree). The entry-count delta (23 → 28) is structural only: v0.1.0's lone malformed `content\` directory entry (backslashed, trailing `\`) is replaced by 6 explicit forward-slash directory entries (`pandemonium-<ver>-windows-x86_64/`, `content/`, `content/entities/`, `content/factions/`, `content/maps/`, `content/rules/`). Every extracted byte and filename is the same set.
