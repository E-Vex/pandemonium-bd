## 8 Risks and surprises

- **The one-line diff is the whole port.** Verified against the
  downloaded 0.23.0 crate source before editing:
  `with_error_callback` takes `FnMut(cpal::Error)` (re-exported as
  `rodio::CpalError`), and `DeviceSinkBuilder::from_default_device`,
  `open_sink_or_fallback`, `MixerDeviceSink::{mixer, log_on_drop}`,
  `SamplesBuffer::new`, and `Source::amplify_normalized` are all
  unchanged — then proven by the full gate. What the bump brings is
  cpal 0.18's backend work (its changelog: WASAPI `Stream::drop`/
  `play`/`pause` no longer panic when the device is lost; the ALSA
  sub-millisecond timeout fix; the unified error taxonomy), inherited
  under the same probe path.
- **cpal 0.18.2 on Windows shares wgpu 30's windows-core 0.62 pins**
  and drops the old windows-sys 0.45 chain — a tree shrink, not a
  growth; the audit gate confirms zero advisories in the new tree
  (344 deps). The historical Windows client-crash class
  (WINDOWS_CI_CRASH.md, closed at a2bc546) is a rodio/cpal
  multi-probe issue — the probe path itself is unchanged by 0.23 (the
  same `from_default_device` → `open_sink_or_fallback` chain behind
  the same `/dev/snd` pre-check and `PANDEMONIUM_AUDIO_PROBE` kill
  switch), and the PR's CI Windows legs are the live proof.
- **The machine cannot hear**: whether 0.23 sounds identical is the
  owner's re-test on real hardware (the A14 sessions, or a quick
  session); every machine claim here is about wiring, counting, and
  the null arm's documented behavior.
- The verification host: 2-core sandbox, Debian trixie userland, Xvfb,
  Mesa llvmpipe via the §9 userland EGL recipe; rodio/cpal built
  against a userland libasound 1.2.14 through pkg-config — the same
  route CI's `libasound2-dev` provides on the ubuntu runners.
