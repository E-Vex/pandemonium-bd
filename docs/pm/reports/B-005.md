### 3.1 P-1 — ci.yml sets a fixed, documented PROPTEST_RNG_SEED for the test jobs; it provably takes effect; local runs stay random

**The change.** ci.yml's `test` job (the 6-leg matrix: 3 OSes × dev/release) carries
`env: PROPTEST_RNG_SEED: "20261011"` with a comment block stating what it does,
where the value came from, and the rotation rule (by brief only, like the runner
pins, A-201). The run step echoes the seed in force before `cargo test`, so
every leg's log is self-describing — verified: the workflow file at `64c48d5`
and on the final head; the CI job logs below show the echo line live.

**The mechanism (source-verified, not docs-claimed).** In the shipped
proptest 1.11.0 source (~/.cargo/registry, the version the repo's
Cargo.lock pins): `config.rs` defines `RNG_SEED = "PROPTEST_RNG_SEED"`,
parses it as u64 into `Config::rng_seed` as `RngSeed::Fixed(n)`
(`FromStr`, config.rs:206-212), and `contextualize_config` applies env vars
*after* each test's own `#![proptest_config(...)]` (the `proptest!` macro
calls it on the in-file config — sugar.rs:160/175), so the pin governs even
the ai fuzz's committed 4096-case config; `runner.rs:316-320` builds every
TestRunner's RNG from it (`TestRng::default_rng(seed, …)`), and
`rng.rs:383-400` maps `RngSeed::Fixed(seed)` → `ChaChaRng::seed_from_u64`
(with the variable unset: `RngSeed::Random` → `from_os_rng` — random per
process).

**The proof it takes effect — same cases on two runs.** A scratch-crate
harness (agent-local, outside the repo, `proptest = "=1.11.0"`) records every
drawn case of two properties (one full-i32-domain pair like the fx properties,
one ranged u64 pair) to per-run log files; the driver
(`scripts/logs/seed-proof-result.txt`) then compares them:

| Comparison | Result |
|---|---|
| run A (seed 20261011) vs run B (seed 20261011) | **byte-identical logs — 512/512 cases each, both properties** (same cases on two runs) |
| run A (seed 20261011) vs run C (seed 424242) | differ — the seed value governs the stream |
| run D (no seed) vs run E (no seed) | differ — **local runs stay random** |

How it takes effect on CI: every leg of every run reads the same env var, so
every property in every test binary draws the identical case stream — the
harness proves the stream-identity property of exactly this mechanism at
exactly this proptest version, and the CI echo proves the variable is in
force in the runner environment. The strongest in-repo observable would be a
deliberately failing property (proptest prints its seed only on red); the
repo has none — all properties are green — which is precisely why the
scratch harness substitutes direct case-stream observation.

**The seed is green (the STOP check).** `PROPTEST_RNG_SEED=20261011 cargo
test --workspace` → 574/574 dev, 0 failed; `--release` → 569/569, 0 failed

## 8. Risks and surprises

- **A pinned PR seed narrows per-push exploration** — every PR now draws the
  identical cases. That is the deliberate trade (deterministic reds at the
  gate, fresh regions at volume in the nightly sweep), and it is why the two
  halves ship together: the sweep's run-id seed explores what the pin freezes.
  The seed must rotate by brief from now on; a silent change would be a
  coverage regression no review can see (policy doc, seed-policy rule 1).
- **The nightly sweep's red path is designed but unfired** — the failure
  summary (`if: failure()`) has never run live because both tiers were green
  on the dispatch. Its content is three `echo` lines whose inputs are
  environment variables in force; the first real red will be its first live
  proof (the same honest note B-002R §8 makes about the aggregator's red
  path).
- **The CI runner measured slower than the 2-core design host** for the
  sweep (fx 25.9 s vs 19.6 s; ai 114.1 s vs 97.9 s) — the counts are sized
  with room to spare either way, but anyone re-tuning counts should re-measure
  *on the runner*, not on a workstation.
- **`github.run_id` is stable across re-runs of the same run** (a re-run is a
  new attempt of the same run id): a re-run nightly re-sweeps the *same*
  seed. That is arguably a feature (a red is re-runnable to the same draws
  in place), and the failure summary's local repro command works regardless.
- **B-002R's biggest finding stands:** master is not branch-protected (§11).
