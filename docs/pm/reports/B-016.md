## Notes and decisions

- **The defaulting lives in the constructors, not the gate.** The brief's "hand-built TrivialWorld constructors default the roster to every structure kind in `kinds`, with an explicit override" is implemented as `with_default_roster()`/`with_roster()` and applied at every literal, rather than teaching the gate an "empty roster means unrestricted" fallback: the gate reads the roster literally, so roster membership stays authoritative in every world — an empty roster genuinely fields nothing. The content path never sees the defaulting at all (`ContentBundle::world` fills from the faction), so FD-4's "adding content means adding a file" and FD-6's seam discipline are untouched.
- **The roster is never hashed — three ways.** `TrivialWorld::content_hash()` does not read the field (pinned by `the_roster_is_never_hashed`: worlds differing only in roster hash identically, and the fixture encoding version stays 4); `ContentBundle`'s hash is computed before `world()` runs and its `encode_factions` has always encoded the *authored* roster (so the registered content hash could not move — verified by the identity pin); and replays record the world hash, so pre-B-016 recordings re-verify against the new code unchanged.
- **Gate order is load-bearing.** The roster check sits between the is-structure check and `check_economy` deliberately: `InvalidTarget` for "the faction does not field this" matches the is-structure reason (both are "not a buildable target here"), and winning over the economy checks means a restricted roster cannot be probed with ore-spending side effects — the refusal is total (no spend, no site, no builder order).
- **The A11 accommodation is the only semantic test change**, and it is the gate working as specified: the test was pinning the loose gate's ore-node buildability as a geometric fixture choice, not as a claim about roster policy. The replacement structure is footprint-identical, so the geometry the test exists to pin is bit-for-bit the same scenario.
- **Authoring note for the variant briefs (B-019/B-020).** The inline-variant shape this package enables: a mission file that wants a restricted build set will carry its roster decision inline (ADR-0201 §6) and the seam will hand `world()` a per-mission override via `with_roster` — the field and the override constructor are now in place, and the mission-less path's full-Legion roster keeps every existing mission byte-identical in behaviour.
- The frozen content (no files under `content/factions` or `content/rules` added) and every golden were verified unmoved at the end of the run.
