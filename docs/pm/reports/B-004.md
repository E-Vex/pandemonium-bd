## 3. Evidence per acceptance criterion

### 3.1 Diagnosis (brief §1) — test-premise defect; fx is correct

**The documented contracts** (`crates/fx/src/fixed.rs`):

- Module docs (lines 5–14): "`mul` and `div` use 64-bit intermediates and round toward zero. Results that cannot be represented **saturate** to `Fx::MAX` / `Fx::MIN` instead of panicking or wrapping."
- `div` (lines 118–133): "Divides, rounding toward zero; **saturates when the quotient does not fit**. Division by zero saturates by the sign of the dividend."
- `checked_div` (lines 141–149): "Checked division: exact, or `None` on a zero divisor **or a quotient that does not fit**."

**The failing input** (CI run 38076181010, master `c876174`, job `tests (ubuntu-24.04, release)`): a = −393216, b = −1 (raw values). The true quotient is ((−393216)·2^16)/(−1) = 25,769,803,776 raw = 393216.0 — far above i32::MAX (2,147,483,647). So `checked_div` → `i32::try_from` fails → **`None`** (correct: the quotient does not fit), and `div` → clamp → **`Fx(2147483647)` = `Fx::MAX`** (correct: saturation). The observed pair (`left None`, `right Some(Fx(2147483647))`) is exactly both contracts honoured. **Verdict: the premise, not the implementation.** The guard `b != 0` plus the ±2^20 draw ranges admit every input with `|a| > 32768·|b|` (as small as |a| = 32769 with |b| = 1), where the quotient leaves i32 and the two contracts *deliberately differ* — the old test asserted they never differ.

**Local reproduction on untouched master** (proving the mechanism, not just the arithmetic):

```
$ PROPTEST_RNG_SEED=777 PROPTEST_CASES=2000000 cargo test -p pandemonium-fx --test properties checked_div_agrees_in_range
  left: `None`,
 right: `Some(Fx(-2147483648))` at crates/fx/tests/properties.rs:76.
minimal failing input: a = 294913, b = -1
```

— the negative-saturation twin of the CI case (a > 0, b < 0: the quotient leaves through the bottom; `div` saturates to `Fx::MIN`). Reproduced on the pristine tree at 2,000,000 cases; the seed proptest appended to the tracked regressions file was **reverted** (regressions policy rule 4 — the red converts to a named test, below).

**Flake-rate measurement** (why it was rare and why a re-run went green): Monte-Carlo over 20,000,000 uniform draws in the old ranges plus the closed-form count agree: per-case failure probability **p ≈ 1.485e−5** (1 in ~67,300). Per 256-case CI leg ≈ 0.38 %; per full 6-leg CI run (3 OS × dev/release) ≈ **2.26 % — roughly one red per 44 CI runs**. CI #77 (≈70 prior run-opportunities since M0) was on schedule, not an anomaly; the failure at case 18 of 256 was an early hit of the waiting-time distribution (conditionally ~7 % likely at that index), and the same tree passing elsewhere was exactly the coin landing the other way. (Proptest's integer ranges sample uniformly — `rand` `Uniform::new` in `proptest-1.11.0/src/num.rs` — so the count is the true rate, not a modelling guess.)

**STOP conditions checked:** fx returns `None` exactly where the result is *un*representable and `Some` with the exact quotient where it is (proven below by 10^6+ oracle-checked cases in both profiles) — not the reverse anywhere. Not an fx defect; no golden at risk; no test weakened (§3.2). Proceeded per the brief.

### 3.2 Test-side fix (brief §2)

**The named deterministic test** — `checked_div_pins_the_flake_and_representability_boundaries` (`crates/fx/tests/properties.rs`), every input written out, each expected value pre-verified by standalone arithmetic (`i128` shift/divide) before being pinned:

| Pin | Inputs (raw) | True quotient | Expected |
|---|---|---|---|
| CI #77 case | a=−393216, b=−1 | 25,769,803,776 | `checked_div` `None`; `div` → `Fx::MAX` |
| Local twin (seed 777) | a=294913, b=−1 | −19,327,418,368 | `None`; `div` → `Fx::MIN` |
| Quotient exactly at MAX | `Fx::MAX` / `Fx::ONE` | 2147483647 | `Some(Fx::MAX)` |
| Quotient exactly at MIN | `Fx::MIN` / `Fx::ONE` | −2147483648 | `Some(Fx::MIN)` |
| MIN / −1 (classic overflow) | `Fx::MIN` / `−Fx::ONE` | 2147483648 (one past MAX) | `None`; `div` → `Fx::MAX` |
| Edge just inside | a=32767, b=1 | 2,147,418,112 | `Some(Fx::from_raw(2147418112))` |
| Exact edge, +∞ side | a=32768, b=1 | 2147483648 | `None` |
| Exact edge, −∞ side | a=32768, b=−1 | −2147483648 | `Some(Fx::MIN)` |
| Exact edge, negative dividend | a=−32768, b=1 | −2147483648 | `Some(Fx::MIN)` |

| Zero divisor | `Fx::MAX` / `Fx::ZERO` | — | `None` |

The |a| = 32768 edge is the heart of the defect: the quotient is exactly 2^31, representable **only** when the signs send it to MIN — the deterministic test pins both sides of that sign flip. The brief's "minimal failing input a=−393216" is proptest's *best-effort* shrink, not the mathematical minimum (±32768 with |b|=1); both are pinned.

**The re-founded property** — `checked_div_is_exact_or_none_against_the_i128_quotient_oracle`:

- **Oracle:** `q = ((a as i128) << 16) / (b as i128)` recomputed straight from the raw values — 128-bit headroom (no i64 ceiling at 2^47), truncation toward zero (identical integer-division semantics), fully independent of the code under test. Where `i32::try_from(q)` succeeds: assert `checked_div == Some(Fx::from_raw(q))` **and** `div == Fx::from_raw(q)` (the clamp is provably a no-op in-range — this is the old "agrees" claim, now guarded by the oracle). Where it fails: assert `checked_div == None`. `b == 0`: `None`.
- **No self-referential guard:** the strategies are `proptest::num::i32::ANY` × `ANY` — the full domain, no draw ranges, no `if b != 0`-style premise. Every branch is decided by the oracle, so the flake region (tiny |b|, large |a|) is *exercised*, not excluded — ~1.5e−5 of uniform draws land in it, now asserted `None` instead of miscalled red. The property is strictly stronger than the one it replaces: it covers the old valid region (asserting both ops against the oracle there) *plus* the entire unrepresentable region *plus* b = 0.

**≥10,000 cases per property, dev and release** (brief §2.3) — verification-time runs via `PROPTEST_CASES=10000` over `PROPTEST_RNG_SEED` ∈ {20261011, 777, 424242, 999983, 31337}:

That is ≥1,000,000 oracle-checked cases per property per profile across the five seeds (the env var applies to every property in the binary). **No `.proptest-regressions` file committed:** the only file of that name in the tree is the pre-existing one-seed file from `be8787e` (green, a legitimate guard per policy rule 2 — untouched); the seed appended by the local red was reverted; `git status` clean of regressions files at every commit.

## 9. Proposals (not implemented)

- **P-1 — deterministic proptest seed in PR CI.** Add `PROPTEST_RNG_SEED: <literal u64>` (and optionally `PROPTEST_CASES: "10000"`) to the `env:` of ci.yml's `test` job. Verified support: proptest 1.11.0 reads `PROPTEST_RNG_SEED` as u64 (config.rs; empty/unset ⇒ random per process) and applies env config after in-file config, so it governs all 21+1 properties on all six legs uniformly. *Effect:* every PR runs the identical draw sequence — a red PR re-runs red on the same inputs and shrinks to the same case, so **a red PR is never luck and never flakes**; the CI #77 class is eliminated at the source. *Costs measured:* the fx suite at 10k cases adds ~2 s per leg (dev) — noise against the ~10 min legs. *Trade-offs:* (a) every PR sees the same inputs — seed-dependent regions go unexplored between rotations, so a green PR is only "green on the pinned seed"; the seed becomes a frozen constant that must rotate **by brief** (exactly like the runner pins and for the same reason — never by drift); (b) the pinned seed must be published in ci.yml, which slightly narrows the surprise value of the fuzz for future agents reading the workflow.
- **P-2 — random seeds and larger case counts in nightly.** A `proptest` job in nightly.yml: no seed env (proptest's default random-per-process), `PROPTEST_CASES=100000` for the fx suite (~20 s dev, measured) and a separate tier for the ai fuzz (each case constructs two sims and steps them: ~93 s per 10k-case run measured, so 100k ≈ 15 min — its own job with its own timeout). *Effect:* nightly explores fresh input regions at volume — the exploration PRs lack under P-1; a red logs its seed (proptest prints it on failure), which reproduces locally via `PROPTEST_RNG_SEED=<seed>` and then converts to a named deterministic test per the regressions policy. *Trade-offs:* a nightly red cannot be re-run to the same draws in CI (the seed lives in the log, not the run) — the local reproduction is the workflow; runner-minutes are dominated by the ai fuzz tier; and the two proposals only work as a pair (deterministic PRs without nightly exploration freeze coverage; nightly exploration without deterministic PRs keeps the flake class in the merge gate).
- **P-3 (lesser, optional) — pin the *floor* too:** if P-1 is adopted, record in ci.yml a short comment pointing at this report and the policy doc's defect-class section, so the seed's rotation cadence and the reason it exists stay greppable next to the value itself. (No code change; included so the PM can drop it if the comment is judged noise.)
