# B-022 — Pack validation hardening (report)

**Branch** `b/B-022-pack-validation` · **Base** master `a78f9dc` (`a78f9dc9…`, the A-020 merge, verified against `origin/master` before the first commit) · **Status**: done, all verification green, goldens unmoved.

Four defects in the client's pack/presentation layer, three of them in one file (`crates/client/src/pack/mod.rs`), one in the renderer's pipeline bootstrap. All four share one shape: **user-authored pack data takes a path the code's own documentation promises is guarded, and the failure is either a crash, a silently wrong tier, or a red CI leg.** None touches the simulation; the goldens are bit-identical throughout.

The triggering defect is the red Windows CI leg on master (run 40745402773, both profiles): `pack::tests::absolute_paths_are_rejected` panicked because `AssetPack::load` returned `Ok` for a Unix-absolute path — `Path::is_absolute` answers for the host OS only, and `/etc/passwd` is *relative* under Windows path grammar.

## The four defects

### 1. Absolute-path rejection was platform-dependent (the red CI leg)

`resolve_ref`'s check — `Path::new(asset).is_absolute()`, under the comment *"Reject absolute paths on any platform"* — answers for the host OS only. On Windows, `/etc/passwd` has no drive or UNC prefix, so it is *relative* there: the manifest loaded, `root.join` re-anchored it to the drive root (`C:\etc\passwd`), canonicalization failed, and the entity silently placeholdered while the pack reported success. The pinned test then failed on `expect_err` (the panic message in the CI log shows `Some(AssetPack { … entities: {} })`).

A pack manifest is portable data; the rejection is now spelled for all platforms at once (`path_is_absolute_anywhere`): Unix roots (`/…`), drive-less Windows roots (`\Windows`), UNC and verbatim prefixes (`\\server`, `\\?\C:\`), and drive specifications (`C:\`, `c:/`, and the drive-relative `C:foo`, which Windows resolves against the drive's current directory — never the pack root).

**The one deliberate strictness** (a trade, recorded here for the owner): a relative name starting `c:` — a legal Unix filename, but unopenable on Windows regardless — is now refused on every platform, so a pack that loads anywhere loads everywhere. The containment guarantees (`..` rejection, canonicalize + component-wise `starts_with`) were and remain correct on both platforms.

### 2. Extension comparison was case-sensitive while documented case-insensitive

`extension_of`'s doc comment has claimed since its introduction (`cf5dd75`) that `"PNG"` matches `"png"` — the code never lowercased. Consequences on every platform: a v2 `icon: "Rifleman.PNG"` was the **fatal** `IconNotPng` (the whole pack refused over an extension Windows and macOS consider identical), while an uppercase v1 `.PNG`/`.GLB` silently placeholdered instead of migrating to the skin/model tier, and `kind_of` returned `None` for uppercase extensions. `extension_of` and `kind_of` now lowercase for comparison only — the file on disk is still opened by the author's exact spelling.

### 3. `ground_offset` accepted NaN/inf (invisible model behind a green evidence line)

A-144 defined no range for `ground_offset`, and RON parses `NaN`/`inf` into `f32`. A manifest with `ground_offset: NaN` survived the whole tier chain — GLB loads, model pass uploads, the positive `entity model '<kind>' loaded` line prints — and then every vertex's Y is NaN, `clip` is NaN, and the model rasterizes nothing, with no diagnostic. The loader now requires a finite value (`ValueOutOfRange { field: "ground_offset", allowed: "any finite value" }`) — the same treatment `scale`'s range check already gives a NaN scale. A-144's "no range" reading is refined, not reversed: `1e6` still loads (pinned), any finite lift still loads, only non-numbers are refused.

### 4. The pack bootstrap texture bypassed the decode guards (startup crash from ordinary art)

`load_pack_texture` (the terrain pipeline's first-texture bootstrap) fed user pack art straight into `image::open` + `create_texture`, bypassing the renderer's own documented guard chain (`MAX_TEXTURE_DIMENSION` 2048, `MAX_TEXTURE_FILE_BYTES` 64 MiB). A pack PNG with a side past the device's `max_texture_dimension_2d` (8192 under default limits) decodes fine and then fails wgpu validation — the default uncaptured error handler **panics at startup**, while every other asset failure degrades to a fallback tier. Second order: a grayscale PNG sized just under the image crate's 512 MiB decode budget expands ×4 through `to_rgba8` into a ~2 GiB transient allocation — the exact decode bomb `texture.rs`'s guards exist to stop. The path now decodes through `texture::decode_png` (the same guarded path the skin tier uses); guard failures fold into the existing `None` → `white_fallback_texture` tier.

## Findings reported to the owner (found in the B-022 sweep, NOT fixed here)

The sweep that found these four also surfaced the following, each with its trigger, left for triage — none is in this branch's scope, and two are already registered:

1. **Replay decode pre-allocation** — `Vec::with_capacity` off untrusted count prefixes (`replay/src/lib.rs` 160–175, 470–472): a ~50-byte hand-crafted replay with a huge `command_count` aborts on an OOM allocation. **Already registered as DEBT-018** (out of the declared threat model; tripwire: the first feature that exchanges replays between parties). No action taken, per the register.
2. **`alpha_plan`'s cross-default asserts are reachable from mission content in release** — a solo `min_wave: 20` above the default `wave_size` loads cleanly and then panics the windowed client at mission start. **Already recorded as B-021's Open issue 1** (the owner's `Result`-channel decision). No action taken.
3. **Content integer validation gaps** (`content/src/validate.rs`): footprints, start offsets, and ReachArea circles are unbounded RON `i32`/`u32`, and the boundary math mixes them in plain `i32` — e.g. `Footprint((w: 4294967295, h: 1))` passes every check through `w as i32 == -1` and later aborts in `Sim::new`'s `claim_footprint` allocation (~34 GiB, release) or panics the validator (debug, `x + w as i32` overflow). Hand-authored content only (SECURITY.md's declared model), but the project's own standard is precise loader errors. Suggested shape: range validation at load (footprint ≤ map dimension, offsets in bounds, circle fields bounded) + checked/i64 boundary math. **Needs a brief** — it touches the content pipeline and every check is behavior-visible to authors.
4. **Mission-player seam mismatch**: the client resolves mission data for `HUMAN` (`PlayerId(0)`, `app/mod.rs:575`) while `tools replay-verify` resolves it for the map's first start's player (`verify.rs:235–239`). Harmless today (objectives are derived, unhashed — ADR-0201), but a map whose first start is not player 0 records and re-simulates different players' objectives, and Phase 2 makes that state-visible. The `mission_data_for_player` doc comment already claims the two agree. **Needs an owner decision** (one law: first-start player everywhere, or `HUMAN` everywhere) before Phase 2 lands.
5. **Soak telemetry hardcodes slots 0/1** (`tools/src/soak.rs:285–303`): a map with starts `[2, 3]` reports every decisive win as "mutual destruction". The repo's content uses 0/1, so no current evidence is affected; worth fixing alongside 3's content-validation brief if non-0/1 maps ever ship.
6. **`bench --ticks`/`--scale` preallocate unchecked** (`tools/src/bench.rs:143`, `scale.rs:144–146`): `--scale 4294967295` panics ("capacity overflow") instead of a usage error. Self-inflicted CLI misuse; a clap range validator each is a one-liner for a tools cleanup brief.
7. **`replay-verify` demands a content directory even for demo-world replays** (`tools/src/main.rs:218`): a stripped install verifying a demo record (which needs no content) errors with "content directory not found" before decoding. Defer `resolve_content_dir` until after the demo-world hash check.
8. **GLB-side non-finite floats** (low): the GLB loader performs no finiteness pass over POSITION/NORMAL payloads, and singular node transforms collapse normals to zero (degenerate flat-glow shading, glam's `inverse()` yielding inf/NaN, contained by `normalize_or_zero`). Both are silent-degradation shapes in the model tier, not crashes; the manifest side (`ground_offset`) is closed by commit `e5fb0ab`. A `world.determinant()` + position-finiteness pass in `read_primitive` would turn both into precise `ModelLoadError`s — model-pipeline territory (ADR-0101), the A-021+ lane's call.
