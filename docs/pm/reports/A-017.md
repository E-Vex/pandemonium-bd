**3.2 Phase 1 — the pure-data GLB loader (A-016 §12) — LANDED.**
`crates/client/src/render/model.rs` (new) with only its `mod model;` line added to `render/mod.rs`. `load(bytes) -> Result<ModelData, ModelLoadError>`: no GPU, no wgpu, unit-testable headless — the module's 30 tests run inside the normal suite. `ModelData { primitives: Vec<PrimitiveData{positions, normals?, uvs?, indices?, material}>, materials: Vec<MaterialData{albedo: Tex-or-Factor, team_color}>, team_color, team_color_materials, ignored_animation_data }` is the plan's shape, completed with the resolution metadata the A-146/A-016 §2 diagnostics need. The pre-parse size check is `MAX_GLB_BYTES = 32 MiB`; the ART_SPEC §10 subset is enforced with 19 precise `ModelLoadError` variants. Acceptance evidence:

- **Valid box parses** — hand-assembled GLB chunks (JSON + BIN built in-test): positions/normals/uvs/indices/material asserted value-for-value (`a_valid_box_parses`).
- **Every rejection path returns `Err`, never a panic** — oversized, not-a-GLB, malformed JSON, truncated BIN, missing BIN, external buffer, external image, missing mimeType, JPEG, WebP, alpha BLEND, alpha MASK, non-TRIANGLES mode (POINTS), missing POSITION, sparse accessor, wrong component type, indices past the vertex count, no default scene, nothing drawable, cyclic hierarchy: each pinned to its precise variant by a dedicated test.
- **Fuzz loop, zero panics** — `fuzz_random_slices_never_panic` (10,000 pseudo-random slices, deterministic via fx's PCG32, seed 0xA017) and `fuzz_mutations_never_panic` (every truncation of the fixture, every single-byte overwrite with 0x00/0xFF/0x20/0x67 at every offset, mangled magics, degenerate short inputs). **The fuzz loop earned its keep before shipping**: it caught a reachable panic in gltf-json's own validator — the crate's POSITION validate hook indexes the accessor table unchecked (`gltf-json/src/mesh.rs:151`), and one corrupted byte in a POSITION accessor index crashes `Gltf::from_slice` during validation. The loader now parses through `from_slice_without_validation` and validates its own subset with total guards (every access `get`-checked, every enum matched with its `Invalid` arm, every range proven before any slice, cycle + depth guards on the node walk) — the exact mutation now returns `Err` like any corrupt file (A-151).
- **team_color resolution unit-pinned via the `names` feature** — present → `Some(0)` with count 1; absent → `None` with count 0 (the model still loads, untinted); multiple → the first wins with `team_color_materials: 2` for the caller's one note.
- **Node transforms baked** (matrix and TRS, translation/scale pinned; normals renormalized), **animations/skins/morph targets counted and ignored** (one fixture carrying all three → `ignored_animation_data == 3`, geometry intact).

## 8. Risks and surprises

- **gltf-json's validator has a reachable panic** (`mesh.rs:151`, unchecked accessor indexing in the POSITION hook). The fuzz loop caught it before it shipped; the loader never runs that validator (A-151). This is worth an upstream report to gltf-rs — the panic is in a *validation* path, the one place a parser library most owes safety. Relayed as §11 item 3.
- **The ADR §4 example's two RON deltas** (A-153): a pack author copying the example verbatim gets two precise errors — good failure modes, but the ADR's text and the implementation differ cosmetically. §9 P2 proposes the one-line ADR example fix at the next docs touch.
- **`UnsupportedVersion.expected` changed 1 → 2** in lockstep with `MANIFEST_SCHEMA_VERSION`: the error remains the precise shape the plan pinned; the one test asserting it moved with the code. Any external consumer grep'ing "expected 1" (none in-tree) would see the change.
- **The loader ignores POSITION min/max** (the crate's validator enforced them; the loader's subset does not need them — A-151): a Blender export always writes them, so this only widens acceptance of hand-crafted files whose positions the loader reads directly and safely anyway. Harmless, recorded here so the phase 3 review knows.
- **The windowed smoke's Xvfb environment** needed a userland EGL stack extracted without root (§4) — the recipe worked exactly as AI-Handoff §9 documents it, which is itself worth knowing for the phase 3 Xvfb machine pass.
