## 1 Summary

ADR-0201's optional last phase, the assessed command-log checkpoint made
concrete: the sim crate's canonical feed loop is exposed as a rehost driver
(`rehost_sim` — the live `Sim` advanced to the saved tick), each objective's
resolution is readable outward (`Sim::objective_states` — a resolved
objective never re-fires its event), and the engine gains
`MatchHost::resume_with_mission` (the log seeded with the recorded commands,
so a recording of the resumed match carries the complete command log). The
client half: a single `mission_save.pdrp` slot beside `settings.cfg` that IS
a replay record (the same recorder `--record` uses), the pause menu's
confirm-gated Save & Quit rung, the main menu's Continue row, and the resume
re-entering unpaused with the HUD seeded from the authoritative statuses.
Zero golden motion; +25 tests.

## 3 Evidence per acceptance criterion

**The rehost seam (ADR-0201 §6: "resume re-simulates from tick 0 through
`run_command_log` and re-hosts from the saved tick").** The rehost shares
the canonical driver's exact construction and feed loop (one loop, two
callers — `advance_by_log`); the rehosted simulation is the one the original
match held at the saved tick: state hash, tick, and id watermark identical,
by A2's re-simulation property over the recorded prefix. Commands:
`cargo test -p pandemonium-sim -- runner::` → 7 passed
(`rehost_matches_the_canonical_driver`,
`rehost_at_zero_ticks_is_the_fresh_construction`,
`rehost_carries_a_mission_without_changing_state` (the A-066
byte-equivalence at the rehost seam),
`rehost_carries_the_resolved_objective_statuses`, plus the pre-existing
trail pins unchanged). Over the real content:
`cargo test -p pandemonium-tests --test mission_campaign` → 8 passed
(incl. `rehost_over_the_real_chapter_matches_the_canonical_driver` and
`resume_with_mission_rehosts_over_the_real_chapter`).

**The resumed host (ADR-0201 §6's caveats, in force).** The host's log
starts seeded with the recorded commands and appends after the seed, so a
recording of the resumed match carries the complete log — pre-save and
post-resume commands alike, in feed order (still replay-recordable); the
controllers restart fresh (nothing is serialized), and no test asserts the
continuation equals the never-interrupted timeline (§6 caveat iii) — what
the tests pin is the resumed instant itself. Command:
`cargo test -p pandemonium-engine -- host::` → 22 passed
(`resume_with_mission_rehosts_at_the_saved_tick`,
`resume_with_mission_carries_the_resolved_objective_statuses`, plus the
pre-existing host pins unchanged).

**The save file (the ADR's "reuses the replay record itself").**
`mission_save.pdrp` resolves through the same `config_dir_from` as
`settings.cfg`; the file is written by the same recorder `--record` uses
(`report::replay_record`: mission id, seed, player setup, the fed command
log, the checkpoint trail, the forced final at the saved tick), and loads
back through the real loader with the record equal. Load-time gates: the
mission id must name a mission the tree carries (membership,
`replay-verify`'s third comparison, applied at load), and the record's
content identity (content hash + map id) must be what that mission bundles
today — a save from changed content is stale and never rehosts. Commands:
`cargo test -p pandemonium-client --bins -- save::` → 6 passed
(round-trip, missing → NoSave, corrupt → Unresolvable, mission-less →
Unresolvable, unknown-mission + changed-content → Unresolvable,
parent-directory creation).

**The Save & Quit rung and the Continue row.** The pause menu's row 7
exists exactly over a live mission (rows 0-6 keep their indices in every
layout; a plain match keeps its six rows); the main menu's Continue row is
appended after Quit (the last row — every existing main-menu index keeps
its meaning in every layout, save or no save, so the a010/a012 Xvfb walks
are untouched by design). Both are confirm-gated / one-click respectively,
and the wiring round-trips: Save & Quit lands at the menu with the host
dropped and the in-memory save set only on a successful write (a failed
write or a disabled persistence leaves no save — the row never offers a
save that is not on disk). Commands:
`cargo test -p pandemonium-client --bins -- save_wiring::` → 6 passed;
`cargo test -p pandemonium-client --bins -- screens::` and `-- ui::`
carry the machine/render row laws (incl. the updated B-026 count test,
8 over a live mission — updated, not weakened: the law is rows 0-6 keep
their indices, and the count reflects the new row).

**The resume path (the ADR's "deterministic for a given resume point").**
`resume_mission` rehosts over the record's own seed and player setup
(resume re-runs the match's identity, never re-rolls it), enters unpaused
with no cutscene, seeds the HUD's objective tracker from the authoritative
statuses (an objective resolved before the save never re-fires
`Event::ObjectiveState`), resumes the checkpoint trail from the save's own
record, and a later `--record` of the resumed match opens with the save's
own commands and carries everything after them — the decoded record names
the same mission id and seed. Evidence:
`save_wiring::resume_rehosts_at_the_saved_tick_and_hash` (tick, hash, log,
unpaused, no cutscene, the trail, the HUD equality, the continuation
moving, the complete record) — see §3 above.

## 8 Risks and surprises

- The scripted opponent emits commands during the recorded window (the log
  carries the human's and the AI's commands in feed order — the runner's
  law, the same shape every replay records); the wiring pins assert the
  human's move opens the log rather than a fixed count, which is the
  honest shape.
- The catch-up cap means one long `advance` does not step in bulk — the
  wiring helpers step in 16 ms frames (the existing tests' shape); this is
  a test-fixture fact only, nothing in the product changed.
- A crafted save that re-encodes with a valid checksum is out of the
  declared threat model (DEBT-018's stance; `replay-verify` shares the
  exposure). Casual edits fail the trailing checksum.
- Local evidence runs with a stale `mission_save.pdrp` on the machine are
  unaffected by design: the Continue row is appended after Quit, so every
  index-driven walk keeps its arithmetic with or without a save (A-219).
